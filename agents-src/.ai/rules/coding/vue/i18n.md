Every string a user reads is a translation key. Never write a literal into a template, a notification call, or a validation message.

This includes what is easy to forget: button labels, placeholders, empty-state text, table headers, dialog titles, chart axis labels, accessible names and `aria-label` values.

## Organization

Keys are namespaced by the page or component that owns them, mirroring the structure the reader already knows:

```
product.list.title
product.form.nameLabel
common.action.save
```

Genuinely shared strings — actions, units, generic states — live under `common`. Never reach into another feature's namespace to reuse a string that happens to match; the two drift apart the first time one of them needs to change.

Never build a key by concatenating fragments at runtime. A key assembled from variables cannot be found by searching, cannot be checked for existence, and silently renders as itself when a case is missed.

## Values

Pass counts through the library's pluralization rather than choosing a form with a condition. Plural rules differ by language and a condition written for one language is wrong in most others.

Interpolate values as named parameters. Never assemble a sentence by concatenating translated fragments — word order differs by language and the result is untranslatable.

Format dates, times and numbers through the locale-aware formatters, never by hand. See [[coding/typescript/temporal]].

Never hard-code text direction, and never assume a translated string occupies the same width as the original.

## Configuration

Translation files are loaded per locale, not bundled together, so a user downloads only the locale in use.

Locale selection follows the user's stated preference, falling back to what the environment reports. Never hard-code a default locale in a component.
